# Status timing and approval audit

This is a verified partial audit, not a declaration that every workflow works.

## Confirmed defects and repairs

- Phase advancement counted down future-effective statuses before their scheduled Day/Night. The existing preview and advancement functions now share a private start-boundary predicate. Explicit expiry deadlines and pending/manual resolution semantics are unchanged; no existing status records were rewritten.
- Drunk/Sober generated `Hanging` in the expiry-phase field, but the database accepts only Day, Night, Any or no phase. Actual engine → editor → authenticated approval reproduced a database check-constraint failure. The existing engine and editor now retain `Until Hanging` as an event duration with no fabricated phase. Legacy Drunk/Sober labels are normalized safely. Other invalid phase labels are rejected before submission.
- Repeated editor normalization converted blank numeric timers to zero. Blank/null/missing timers now remain unspecified; an explicitly entered zero is preserved.

## Verification

- 371 JavaScript tests passed, with zero failures or skips, including the supplied Transformers DOCX acceptance test. Static build and whitespace checks passed.
- Authenticated-role RPC fixture verified Night0 → Day1 → Night1 → Day2 → Night2 → Day3 boundaries: future timers stay unchanged until their start; preview matches countdown behavior; an untimed pending hanging marker stays pending.
- A ruling generated by the real deterministic engine and normalized by the actual editor was queued, approved and advanced through public RPCs. Both Drunk/Sober markers persisted with null numeric timers and remained pending after phase advancement.
- All integration fixtures use BEGIN/ROLLBACK, not live game simulation. No fixture game remained after verification. Role simulation is database integration coverage, not a fresh browser password-login test.
- Migration `20260906020625_preserve_future_status_timers.sql` was applied and verified. Supabase-guided least-privilege checks retain the helper in the private schema with no browser EXECUTE permission. Existing RPC permissions are unchanged. Security advisors remained at 45 warnings and one informational notice, unchanged from the preceding audit.
